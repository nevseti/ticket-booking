# ADR 0005. Оплата — сага с компенсацией, покупка — одна транзакция

- Статус: принято
- Дата: 2026-10-23

## Контекст

Покупка затрагивает внешний сервис — банк. Держать транзакцию БД открытой на время
сетевого вызова нельзя: блокировки удержаний и соединение из пула висели бы секундами,
а при пиковой нагрузке пул бы закончился. Распределённая транзакция с банком невозможна.
При этом требование задания: «покупка — одна транзакция: погасить удержание, создать
заказ, пометить место проданным», «при отказе удержание освобождается».

## Решение

Сага из коротких локальных транзакций; состояние — в `orders.checkouts`:

| Шаг | Что происходит | Состояние |
|---|---|---|
| 1 | удержания продлеваются на время оплаты, фиксируется снимок позиций и сумма | STARTED |
| 2 | списание в банке — **вне** транзакции | — |
| 3a | успех: отметка оплаты | PAID |
| 3b | **покупка одной транзакцией**: погасить удержания, `sold_seats`, заказ, билеты, события | COMPLETED |
| 4 | отказ / таймаут банка → компенсация: освободить удержания | FAILED |
| 5 | покупка не удалась после оплаты (удержание истекло, место продано) → компенсация: возврат денег + освободить удержания | FAILED |

- **Идемпотентность.** Клиент передаёт `Idempotency-Key`; пара (пользователь, ключ)
  уникальна, а банку передаётся id саги как ключ платежа — повтор не спишет деньги дважды.
- **Восстановление.** `recover()` продолжает сагу после сбоя процесса: для STARTED
  спрашивает банк о платеже по ключу; для PAID повторяет покупку или возвращает деньги.
  Вызывается фоновым воркером для «зависших» саг (этап 6).
- **Банк** — за интерфейсом `PaymentGateway`; в MVP `FakePaymentGateway` с тестовыми
  картами (`tok_ok`, `tok_decline`, `tok_timeout`), задержкой и долей отказов из настроек.
- **Защита от двойной продажи на покупке:** условный UPDATE удержаний (только свои и
  активные, количество должно совпасть) + PK `sold_seats` + уникальность
  `tickets(event_id, seat_id)`.
- **Билеты** — код с HMAC-подписью секретом сервера; проверка на входе без похода в БД
  за подписью, плюс проверка существования билета.

## Последствия

- Отказ банка и любые сбои не оставляют «зависших» мест: компенсация освобождает их.
- Пользователь получает итог синхронно (оплата-имитация отвечает за ~0,3–1 с);
  с настоящим провайдером шаг 2 стал бы асинхронным (вебхук), структура саги не меняется.
- Возвратов по инициативе пользователя нет (условие задания).
