# ADR 0002. Развёртывание: Docker Compose на VPS, nginx + Let's Encrypt, CD через GHCR

- Статус: принято
- Дата: 2026-10-13

## Контекст

MVP разворачивается на одном VPS. Kubernetes и микросервисы исключены условиями задания.
Нужны HTTPS (HTTP/2 для SSE, cookie с флагом Secure) и автоматическая выкладка.

## Решение

- **Docker Compose** описывает весь прод: `nginx`, `api`, `worker`, `migrate`, `postgres`,
  `redis`, `rabbitmq`, `certbot`.
- **Два образа:** `api` (бэкенд; роли api/worker/migrate различаются командой запуска) и
  `web` (сборка SPA + nginx).
- **nginx** — единая точка входа: TLS, статика SPA, обратный прокси `/api` → `api:8000`.
  Фронтенд и API на одном origin, поэтому CORS не нужен.
- **Let's Encrypt** через certbot (проверка HTTP-01). При старте nginx сам выбирает
  конфигурацию: HTTP, пока сертификата нет, и HTTPS, когда он появился.
- **Миграции** — отдельный одноразовый сервис `migrate`; `api` и `worker` стартуют только
  после его успешного завершения.
- **CI/CD (GitHub Actions):** `CI` (линтеры, тесты, сборка) на каждый пуш; `Deploy` после
  зелёного CI на `main` собирает образы, публикует их в GHCR с тегом-хэшем коммита и по SSH
  выполняет `remote-deploy.sh` на сервере.

## Последствия

- Любой коммит в `main` автоматически оказывается на сервере; версия видна в `/api/health`.
- Откат — повторный деплой предыдущего тега (`IMAGE_TAG` в `.env` + `docker compose up -d`).
- Простой при деплое — секунды на перезапуск `api` (одна реплика). Для курсового MVP
  приемлемо; при необходимости — две реплики api за nginx.
